- All input fields have associated <label> elements to ensure proper screen reader accessibility.
- aria-label attributes are used for forms to describe their function clearly.
- Button text is descriptive (e.g., "Log in", "Register", "Log out"), ensuring clarity.
- All forms are keyboard-navigable, and users can submit using the Enter key in any field.
- Semantic HTML and logical DOM structure support assistive technologies effectively.

Dashboard page
- Clear headings and labels (e.g., "Welcome to your Dashboard", "Your Games") support screen readers and 
  provide easy navigation.
- Consistent layout and spacing make the page visually scannable and reduce cognitive load.

- Buttons use distinct colors with text labels (“Start Game”, “Game Details”) that are descriptive and 
  keyboard accessible.

Edit Game Page
- Form inputs have clear labels (e.g., "New Title", "New Thumbnail") aiding users with screen readers.
- Color and spacing are used effectively to distinguish sections, helping users with visual processing 
  challenges.
- Accessible action buttons (“Save Changes”, “Delete Quiz”, “Cancel”) are large, high-contrast, and clear 
  in intent.

Edit Questions Page
- Radio buttons for question type are labeled and grouped meaningfully, aiding both keyboard and assistive 
  tech users.
- Form fields have descriptive labels and placeholders, supporting users with memory or cognitive 
  impairments.
- Media attachment buttons ("+ Add YouTube URL", "+ Upload Image") provide alternative ways to enrich 
  content, catering to different user needs.

Start + stop game session
- Color-coded status (“Status: Active” in green) communicates state clearly, with bold font aiding low- 
  vision users.
- Large action buttons (“Advance”, “End Game”, “Session Details”) are spaced apart and easily clickable.
- Text contrast (e.g., white text on colored buttons) meets WCAG AA standards for readability.
